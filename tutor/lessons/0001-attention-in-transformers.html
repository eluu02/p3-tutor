Warm-up 1 min

Recall

From your Deep Learning course: what does softmax do to a vector of scores like [2, 1, 0]?

Check your answer

It exponentiates each score and divides by the total, giving positive numbers that sum to 1, about [0.67, 0.24, 0.09]. Bigger scores get a bigger share. Attention uses exactly this to turn match scores into mixing weights.

The short version: a soft lookup 2 min

Attention lets every word in a sentence look at every other word and pull in the information it needs. Each word asks a question, every word offers a label, and the asking word collects a blend of everyone's content, weighted by how well each label matches its question.

Now the detail. Think of a hash map from your data structures course. A lookup takes a key and returns exactly one value. Attention is a soft version: a query (the question vector) is compared with every key (the label vectors), and instead of returning one value (the content vectors), it returns a weighted average of all of them. The match score is a dot product, so a key pointing the same way as the query scores high (Dive into Deep Learning, 11.3). Because the result is an average rather than a hard pick, every step is differentiable, so the network learns what to ask and what to offer by gradient descent, the same training loop you know from Deep Learning.

Check yourself

In a transformer's self-attention, where do the queries, keys and values come from?

Three different learned projections of one input. In encoder self-attention "all of the keys, values and queries come from the same place", the previous layer's output (Vaswani et al., 3.2.3), each multiplied by its own learned matrix.

The formula, step by step 3 min

Stack the queries into a matrix Q (one row per token), the keys into K and the values into V. The paper's whole mechanism is one line (Vaswani et al., Eq. 1):

Attention(Q, K, V) = softmax( Q KT / √dk ) V

Read it right to left as four moves:

  1. Score: Q KT holds every query dotted with every key. With n tokens it is an n × n table: row i says how well token i's question matches each token's label.
  2. Scale: divide every score by √dk, where dk is the length of a key vector.
  3. Normalize: softmax each row, so each token's weights are positive and sum to 1.
  4. Mix: multiply by V, so each output row is that token's weighted average of all value rows.

Why the scaling? If the entries of q and k are independent with mean 0 and variance 1, their dot product has mean 0 and variance dk (Vaswani et al., footnote 1). With dk = 64, typical scores spread to about ±8, softmax becomes nearly one-hot, and its gradients become extremely small. Dividing by √dk brings the variance back to 1 whatever the vector length (D2L 11.3). It is the same instinct as careful weight initialization in Deep Learning: keep activations in the range where gradients flow.

In code, the four moves are four lines of NumPy:

import numpy as np

def attention(Q, K, V):
    d_k = K.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)            # 1-2: score and scale, shape (n, n)
    scores -= scores.max(axis=-1, keepdims=True)  # numerical safety, same softmax result
    weights = np.exp(scores)
    weights /= weights.sum(axis=-1, keepdims=True) # 3: each row sums to 1
    return weights @ V                          # 4: mix, shape (n, d_v)
Check yourself

Why does the formula divide the scores by √dk before the softmax?

To keep the score variance near one. Unscaled, scores grow with dk and push softmax into "regions where it has extremely small gradients" (Vaswani et al., 3.2.1).

Self-attention, masking and heads 2 min

The transformer uses this one operation in three places (Vaswani et al., 3.2.3). In self-attention, Q, K and V all come from the same sequence. In the decoder, self-attention is masked: scores for future positions are set to −∞ before the softmax, so token i can only use tokens before it, which is what lets the model generate text one token at a time. In encoder-decoder attention, the queries come from the decoder and the keys and values from the encoder.

Multi-head attention runs several attentions side by side, each with its own projections, then concatenates the results. The paper uses h = 8 heads with dmodel = 512, so each head works with dk = dv = 512 / 8 = 64. Like the multiple filters in a CNN layer, different heads can learn to track different kinds of relationships at roughly the cost of one full-size head.

The payoff over the RNNs from Deep Learning: any two positions connect in one step, a path length of O(1) instead of O(n), and the work is matrix multiplication that runs in parallel. The cost is O(n2·d) per layer, because every token scores every other token (Vaswani et al., Table 1), which is why long contexts are expensive.

A common mix-up

It is tempting to read "masking" as deleting tokens from the input. The tokens stay; only their scores in the softmax become −∞. Since e−∞ = 0, those weights are exactly 0, and the remaining weights still sum to 1. The mask changes who each token may look at, not what is in the sequence.

Check yourself

A model has dmodel = 768 and 12 heads, split the way the paper splits. What is dk for each head?

64. The paper sets dk = dv = dmodel / h, so 768 / 12 = 64.

Worked example and practice 2 min

Worked example

Two tokens, dk = 2. Token 1's query is q1 = [1, 0]. The keys are k1 = [1, 0] and k2 = [0, 1], and the values are v1 = [10, 0] and v2 = [0, 10]. What is token 1's output?

  1. Score: q1·k1 = 1 and q1·k2 = 0, because q1 points the same way as k1.
  2. Scale by √2 ≈ 1.414: the scores become 0.707 and 0.
  3. Softmax: e0.707 ≈ 2.028 and e0 = 1, total 3.028, so the weights are 0.670 and 0.330.
  4. Mix: 0.670 · [10, 0] + 0.330 · [0, 10] = [6.70, 3.30]. Token 1 leans on token 1 but still takes a third from token 2.
Your turn

Same keys and values, but now token 2's query is q2 = [0, 2]. Step 1 is done for you: the scores are q2·k1 = 0 and q2·k2 = 2. Scale, softmax and mix to find token 2's output.

Show a solution

Scale: 0 and 2 / 1.414 ≈ 1.414. Softmax: e0 = 1 and e1.414 ≈ 4.113, total 5.113, so the weights are 0.196 and 0.804. Mix: 0.196 · [10, 0] + 0.804 · [0, 10] = [1.96, 8.04]. The longer query gave a sharper focus, which is the variance effect from the scaling section in miniature.

Summary 1 min

  • Attention is a soft lookup: queries score keys, softmax turns scores into weights, and the output is a weighted sum of values.
  • The formula is softmax(QKT / √dk) V; the √dk keeps scores at unit variance so softmax gradients survive.
  • Masking sets future scores to −∞, so their weights are exactly 0; multi-head attention splits dmodel across parallel heads.
  • Any two tokens connect in one step, at a cost of O(n2·d) per layer.
